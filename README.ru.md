Spec OCR Pipeline — кроссплатформенная утилита командной строки, которая превращает PDF-файлы
инженерных спецификаций в проверяемые нормализованные строки и редактируемые Excel-книги. Для
поддерживаемых PDF с текстовым слоем есть детерминированный полностью локальный путь, для сканов —
интеграция с системным Tesseract, а для сложных макетов — опциональные локальные и внешние
AI-провайдеры.

> **Публичная альфа-версия:** основной сценарий уже работает и покрыт тестами, но настройка
> провайдеров, параметры команд и детали выходных файлов ещё могут меняться. Результаты OCR и AI —
> это черновик: перед рабочим использованием всегда проверяйте количества, единицы измерения,
> границы строк, итоги и формулы в книге.

![Демо Spec OCR Pipeline: синтетический PDF преобразован в структурированные строки и Excel-книги](docs/assets/demo.jpg)

## Что создаёт программа

- нормализованный JSONL, который удобно проверять, сравнивать и обрабатывать;
- чистую однолистовую книгу XLSX;
- опциональную книгу коммерческого предложения на основе шаблона;
- данные OCR, отчёты качества и производительности, а также метаданные запуска;
- явный выбор провайдера, чтобы было видно, где данные обрабатываются локально, а где внешне.

Встроенное демо полностью синтетическое, его можно безопасно публиковать. Макеты реальных
документов различаются, а успешное завершение команды не гарантирует правильность каждого
распознанного значения.

## Быстрый старт

Скопируйте HTTPS- или SSH-адрес из меню GitHub **Code**, затем клонируйте репозиторий:

```bash
git clone https://github.com/floze-the-genius/spec-ocr-pipeline.git
cd spec-ocr-pipeline
```

Создайте и активируйте виртуальное окружение.

Linux или macOS:

```bash
python -m venv .venv
source .venv/bin/activate
```

Windows PowerShell:

```powershell
python -m venv .venv
& .\.venv\Scripts\Activate.ps1
```

Установите пользовательское окружение с поддержкой OCR:

```bash
python -m pip install -e ".[ocr]"
```

Контрибьюторам вместо этого нужно установить окружение разработки:

```bash
python -m pip install -e ".[dev]"
```

Запустите однокомандное синтетическое демо из корня репозитория:

```bash
spec-ocr process examples/demo/specification.pdf --output-dir demo-output --quote
```

Демо использует путь для PDF с текстовым слоем и **не** обращается к внешнему AI-сервису. Будут
созданы следующие файлы:

| Файл | Назначение |
| --- | --- |
| `demo-output/ocr.json` | Текст страниц, токены, метаданные и сведения о провайдере |
| `demo-output/rows.jsonl` | Нормализованные строки спецификации для проверки |
| `demo-output/result.xlsx` | Редактируемая однолистовая книга Excel |
| `demo-output/quote.xlsx` | Книга коммерческого предложения на основе шаблона |
| `demo-output/run.json` | Версия, входные данные, параметры, имена результатов и признак внешнего AI |

Команда не перезаписывает существующие результаты без явного флага `--force`. Безопасный
однокомандный путь поддерживает PDF с текстовым слоем и распознаваемой табличной структурой; для
сканов и более сложных документов нужен явный выбор провайдера, описанный в
[руководстве по использованию](docs/usage.md).

## Поддержка платформ

| Возможность | Linux | macOS | Windows |
| --- | --- | --- | --- |
| Основной путь: PDF с текстовым слоем / Excel | Нативно | Нативно | Нативно |
| Tesseract OCR | Системный бинарный файл | Системный бинарный файл | Системный бинарный файл |
| Локальный AI | x86_64 + NVIDIA | Apple Silicon + MLX | x64 + WSL2 + NVIDIA |

Требуется Python 3.11–3.14. Исполняемый файл Tesseract и языковые пакеты устанавливаются
средствами операционной системы и не входят в репозиторий. Локальный AI на Intel Mac, Windows ARM
и нативный CUDA на Windows не проверены; поддержка этих комбинаций не заявляется.

Подробности приведены в инструкциях для каждой платформы:

- [Установка на Linux](docs/installation/linux.md)
- [Установка на macOS](docs/installation/macos.md)
- [Установка на Windows](docs/installation/windows.md)

## Поддерживаемые OCR- и AI-модели

Извлечение текста и семантическое преобразование строк — разные этапы. Для основного сценария
AI-модель не требуется.

| Этап | Поддерживаемые варианты | Поддерживаемая среда |
| --- | --- | --- |
| Извлечение из PDF | `pdf-text` без модели | Linux, macOS, Windows; локально |
| Классический OCR | Tesseract и установленные пользователем языковые данные | Linux, macOS, Windows; локально |
| Визуальный OCR документов | PaddleOCR-VL | macOS или Windows через WSL2; локальные файлы модели |
| Экспериментальный визуальный OCR | dots.mocr из проверенного локального snapshot | Apple Silicon MLX или Transformers в Linux/WSL2 |
| MLX-маппинг | Qwen3 8B/14B и Qwen3.6 35B A3B 4-bit | Apple Silicon macOS; 16-64 ГБ объединённой памяти |
| GGUF-маппинг | Qwen3.6 27B: `qwen36-safe`, `qwen36-balanced`, `qwen36-quality` | Linux или Windows WSL2; llama.cpp; 32-48 ГБ RAM |
| CUDA-маппинг | Qwen3 8B/14B, Qwen3-VL 8B, экспериментальный Qwen3.6 27B GPTQ | Linux или Windows WSL2 с NVIDIA; 12-24 ГБ VRAM |
| API-маппинг | Выбранная пользователем OpenAI-совместимая модель или модель OpenCode | Локальный loopback-сервер или явно разрешённый внешний провайдер |

Команда `spec-ocr models status --json` показывает управляемый каталог локальных моделей для
текущего компьютера. Полная таблица с aliases, исходными ID, backend, объёмом на диске,
требованиями к RAM/VRAM и границами безопасности находится в разделе
[«Провайдеры и поддерживаемые модели»](docs/providers.md). Модели не входят в репозиторий, а запись
в manifest сама по себе не гарантирует лицензионную или аппаратную совместимость.

## Провайдеры и конфиденциальность

Основной путь для PDF с текстовым слоем и системный Tesseract работают локально. Опциональные
провайдеры семантического преобразования могут быть локальными или внешними. Внешний AI-провайдер
может получить текст OCR и, если это включено, изображения страниц. Перед обработкой реальных
документов прочитайте разделы [«Провайдеры»](docs/providers.md) и
[«Конфиденциальность»](docs/privacy.md).
AI-маппинг по умолчанию запрещён: если поддерживаемого детерминированного табличного слоя нет,
`map-ocr` требует явного выбора `--ai-client`.

Авторизуйтесь только в собственной учётной записи провайдера и только в своём окружении. Никогда
не коммитьте, не публикуйте, не запрашивайте и не передавайте API-ключи, сессии OpenCode или
браузера, refresh-токены, cookies, файлы `.env` и экспортированное состояние авторизации. Не
прикладывайте к публичным issues реальные документы или созданные из них OCR-данные и книги.

## Разработка

После установки `.[dev]` выполните:

```bash
python -m ruff check src tests scripts
python -m ruff format --check src tests scripts
python -m pytest
python scripts/check_public_tree.py
```

CI проверяет поддерживаемые версии Python на Linux, macOS и Windows и валидирует собранный пакет.
Аппаратно-зависимые OCR- и AI-среды всё равно нужно проверять на соответствующем компьютере; в pull
request честно указывайте непроверенные комбинации.

Мы приветствуем точечные исправления с синтетическими примерами, регрессионными тестами и ясными
результатами проверки на платформах. Перед созданием pull request прочитайте
[CONTRIBUTING.md](CONTRIBUTING.md), а об уязвимостях сообщайте приватно согласно
[SECURITY.md](SECURITY.md).
