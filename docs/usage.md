# Usage

`spec-ocr` turns engineering specification PDFs into normalized JSONL and Excel workbooks. Use an
explicit extraction and mapping provider so the data path is reviewable.

## Check the installation

```text
spec-ocr --version
spec-ocr doctor
spec-ocr info
```

If the console script is not on `PATH`, use `python -m spec_pipeline.cli` in place of `spec-ocr`.

## Run the synthetic demo

The repository demo contains no customer data. From the repository root:

```text
spec-ocr process "examples/demo/specification.pdf" --output-dir "demo-output" --quote
```

This creates `ocr.json`, `rows.jsonl`, `result.xlsx`, `quote.xlsx`, and `run.json`.
The safe one-command workflow accepts searchable PDFs with a supported deterministic table layer.
It stops with an explanation instead of sending an unsupported document to an AI service. Existing
outputs are preserved unless you explicitly pass `--force`.

The same demo can be run stage by stage for debugging:

```text
spec-ocr extract-ocr "examples/demo/specification.pdf" --provider "pdf-text" --output "demo-output/ocr.json"
spec-ocr map-ocr "demo" --input-ocr "demo-output/ocr.json" --source-pdf "examples/demo/specification.pdf" --output "demo-output/rows.jsonl" --no-image-attachments
spec-ocr export-jsonl-xlsx "demo-output/rows.jsonl" --output "demo-output/result.xlsx"
```

This particular PDF contains a deterministic `PDF_TABLE_LAYER`, so `map-ocr` uses that layer and
does not call an external AI service. Do not assume an arbitrary PDF has the same property.

To exercise the Excel exporter without mapping, use the synthetic expected rows:

```text
spec-ocr export-jsonl-xlsx "examples/demo/expected-rows.jsonl" --output "demo-output/expected-result.xlsx"
spec-ocr export-kp-xlsx "examples/demo/expected-rows.jsonl" --output "demo-output/expected-kp.xlsx"
```

Some exporters require the output directory to exist. A portable way to create it is:

```text
python -c "from pathlib import Path; Path('demo-output').mkdir(parents=True, exist_ok=True)"
```

## Choose the PDF extraction path

For a searchable PDF with a usable text layer:

```text
spec-ocr extract-ocr "/path/to/specification.pdf" --provider "pdf-text" --pages "1-3" --output "work/ocr.json"
```

For a scanned PDF after installing Tesseract and its language data:

```text
spec-ocr extract-ocr "/path/to/scanned-specification.pdf" --provider "tesseract" --lang "eng" --pages "1-3" --output "work/ocr.json"
```

Use `spec-ocr probe-pdf --help` to inspect the available PDF probe arguments. Prefer an explicit
provider in repeatable workflows instead of relying on `auto`.

## Map OCR into rows

Mapping produces one JSON object per row. The core fields include the sample and page identifiers,
position, item name, type or mark, code, manufacturer, unit, quantity, mass, note, and status.

Before mapping a real document, select a provider in [Providers](providers.md) and read
[Privacy](privacy.md). Depending on the provider, OCR text and page images can leave the machine.
`--no-image-attachments` prevents page-image attachments; it does not prevent OCR text from being
sent to an external provider.

`map-ocr` defaults to `--ai-client none`. It will use a supported deterministic table layer when
one is present and otherwise stop without contacting an AI provider. Select `opencode`, `qwen-mlx`,
or `openai-compatible` explicitly when AI mapping is intended.

For a local Apple Silicon MLX mapper:

```text
spec-ocr map-ocr "example" --input-ocr "work/ocr.json" --source-pdf "/path/to/specification.pdf" --output "work/rows.jsonl" --ai-client "qwen-mlx" --no-image-attachments
```

For a local OpenAI-compatible server bound to loopback:

```text
spec-ocr map-ocr "example" --input-ocr "work/ocr.json" --source-pdf "/path/to/specification.pdf" --output "work/rows.jsonl" --ai-client "openai-compatible" --ai-base-url "http://127.0.0.1:8000/v1" --ai-served-model "local-model" --no-image-attachments
```

## Apply a quality gate

Save a machine-readable report and fail on warnings or errors:

```text
spec-ocr map-ocr "example" --input-ocr "work/ocr.json" --source-pdf "/path/to/specification.pdf" --output "work/rows.jsonl" --quality-json "work/quality.json" --quality-fail-on "warning" --ai-client "openai-compatible" --ai-base-url "http://127.0.0.1:8000/v1" --ai-served-model "local-model" --no-image-attachments
```

Always review quantities, units, item boundaries, and workbook formulas before operational use.
OCR and AI output is a draft, not an authoritative engineering record.

## Outputs

- OCR JSON preserves page text, tokens, metadata, and provider information.
- Normalized JSONL is the reviewable interchange format.
- Single-sheet XLSX is generated by `export-jsonl-xlsx`.
- Template-based commercial-proposal XLSX is generated by `export-kp-xlsx`.
- Quality and performance JSON files are optional audit artifacts.

These artifacts can contain the full substance of a source document. Store and delete them under
the same policy as the original PDF.
